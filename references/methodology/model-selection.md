# 模型選擇原則（Model Selection）

> 預分析評估（company SKILL Step 4.0.5）的模型建議依據。
> v2.0 起以**原則**取代寫死型號——型號名每半年就會過時（v1.x 的教訓：決策樹寫死 Opus 4.6，健檢時已被取代）。

## 決策原則

| 情境 | 建議層級 | 原因 |
|------|---------|------|
| 大型/上市 + 年報需解析 | **旗艦層 + 長 context**（如有 1M 選項） | 年報數據需完整保留至最終報告；深挖輪 findings 累積量大 |
| 中型 | 旗艦層或性價比層皆可 | 性價比層品質差異在可接受範圍（見 perf 基線報告） |
| 微型 | 性價比層 | 資料量小，瓶頸在 OSINT 天花板而非模型能力 |
| 使用者明確要求控制成本 | 性價比層，不論規模 | 成本透明原則 |
| **對抗式深挖輪（v2.0）** | **繼承主 session 模型，subagent 不降級** | RFC-007 明確約束：不為省成本用弱模型 |

「旗艦層」「性價比層」以**當前 session 可選的最新世代**為準。判斷方式：你的 system prompt 會標明當前模型與最新可用世代——以那為事實，不要憑訓練記憶推薦型號。

## 呈現格式（預分析評估時）

- 當前使用模型：[從 system prompt 讀取]
- 建議層級：[依上表]
- 原因：[一句話]
- 如果建議與當前不同：「建議使用 [層級/型號] 以獲得最佳品質。如需切換，請開啟新 session 並選擇該模型。輸入『繼續』以當前模型執行。」
